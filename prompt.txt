# 1. PRODUCT VISION

## Application name
Mossy

## Tagline
"Look closer. Discover more."

## Main concept
Mossy is an AI-powered nature exploration companion that encourages people to discover, understand, and collect the plants and natural elements around them.

The application combines:
- AI-powered plant identification.
- Generative AI educational explanations.
- Personal nature discovery journal.
- AI-generated exploration challenges.
- Gamification and collectible achievements.
- A virtual garden that grows as the user explores.
- A cute, evolving mascot that accompanies the user.

Mossy must NOT feel like a generic AI chatbot or a simple plant identification tool.

It should feel like a beautiful, playful, interactive nature discovery game.

The main experience:

**Photograph → Identify → Understand → Collect → Explore → Grow your garden.**

## Target audience
Anyone who enjoys nature, exploring outdoors, discovering plants, learning interesting facts, and collecting achievements.

## Initial scope
Focus on plants and flowers for the first release.

Design the architecture so wildlife identification can be added later without rewriting the application.

# 7. REQUIRED EDGE FUNCTIONS

Implement the following functions.

## identify-plant

Responsibilities:

1. Validate the authenticated user or supported guest flow.
2. Validate the image.
3. Retrieve or process the uploaded image.
4. Call Pl@ntNet.
5. Normalize the identification response.
6. Return ranked candidates.

Example normalized response:

{
  "status": "identified",
  "candidates": [
    {
      "scientific_name": "Bellis perennis",
      "common_name": "Common daisy",
      "family": "Asteraceae",
      "score": 0.91
    }
  ]
}

This is an example response structure, not a hardcoded identification result.

## generate-discovery-content

Input:
- Scientific name.
- Common name.
- Family.
- Available verified metadata.
- Preferred language.

Use Gemini to generate structured content:

{
  "introduction": "...",
  "description": "...",
  "fun_facts": [],
  "observation_tips": [],
  "safety_note": null
}

Validate the response.

Avoid unsupported medical, edible, or toxicity claims.

If information cannot be established reliably, say so.

## generate-missions

Generate structured exploration challenges.

Return:
- Title.
- Description.
- Difficulty.
- Category.
- Reward points.
- Verification criteria.

## verify-mission

Validate mission submissions using available evidence.

Prevent duplicate rewards.

## award-points

Award points through trusted backend logic.

Use transactional logic so rewards cannot be duplicated.
